# 滚动稳定性检查（0.2.11）

日期：2026-11-06。

## 发现与证据边界

批注位于 fixed 顶层浮层，滚动后通过页面观察、rAF 合并和 React 更新视口坐标。浏览器滚动可以由合成线程推进，主线程脚本跟随存在迟滞的可能。

旧构建在正常本地结构的 20 个逐帧采样中，文字下划线与矩形已能保持小于 1 CSS px 相对误差；没有复现用户具体网页的偶发抖动，不将推断写成现场根因。

代码确认两个会增加风险的路径：

1. 每次绘制/图标定位都会对已绑定元素读取和规范化 textContent；失联记录还会全文搜索候选。长正文、多笔标注时增加主线程开销。
2. 文字/图形关联备注图标在视口边缘被 clamp，并且根据当前可见图标顺序动态避让；可见集合变化会导致其相对内容挪位。

## 本轮修改

- 新增独立内容修订钟；几何刷新复用身份校验结果，仍每次读取当前位置和裁剪范围。失联记录也缓存本内容周期的查找结果。
- 文本/DOM变化、href/src/srcset、隐藏状态变化触发内容修订。缓存会检查元素连接状态；链接复用到另一帖子后失效，不牺牲错绑保护。
- 去除备注图标的边缘吸附和动态垂直避让，位置跟随锚点；预览卡片依旧限制在视口内。不同备注位置重合时目前可能重叠，后续需要稳定的分组/展开设计，不能再靠滚动时临时挪位掩盖。
- 不使用全局 flushSync 强推同步，也不添加视觉缓动：这些操作无法解决合成线程/主线程的根本差异，可能增加滚动负载。

## 验证

30 项单元测试、类型检查和生产构建通过。身份校验回归验证 20 次几何读取只取一次身份文本，内容修订后重新验证。
既有 24 组 Chromium 流程通过；新增滚动流程修正测试中按钮固有内边距的度量后通过：整页/内部滚动共 20 个采样帧，文字与矩形相对误差 <1 CSS px；备注接近视口顶端保持相对位置；复用帖子 href 后拒绝恢复。
本轮没有真实站点负载下的性能录制，未量化重负载下改善幅度。

## 剩余限制

fixed 浮层仍依赖主线程更新，无法承诺页面长任务或浏览器合成器异步滚动期间零延迟。后续应对复现站点录制 Performance trace，评估按滚动容器分组的原生随动图层；不能直接把所有浮层移入宿主元素，后者会重新引入 clipping、transform、层叠和虚拟化问题。
