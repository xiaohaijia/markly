# Markly 稳定性架构审查

日期：2026-11-05。审查基线 0.2.7；本轮维护构建 0.2.8。

## 结论

现有 WXT / React / Shadow DOM + SVG / IndexedDB 的分工可以继续使用；没有证据表明换框架或换成 Canvas 就会解决定位和生命周期问题。应先收紧坐标、内容身份、写入确认和生命周期边界。当前结果支持继续测试，不是公开发布认证。

## 发布前仍需处理

以下是代码审查确认的设计边界，不表示均已做现场故障复现。

### P1：持久化开关状态与生命周期

App.active 仅在 React 内存中。用户关闭后，同源刷新、注册脚本自动加载仍可重新显示；关闭时页面观察和定时发现仍运行。
建议：后台持有按标签页/源划分的会话状态，新文档先查询状态再展示；关闭时停止非必要观察，重新开启时完整校准 URL、锚点和数据。
验收：关闭后刷新/后退/恢复 BFCache 保持关闭；重新开启不串页；已授权和临时启用两条路径一致。

### P1：写入与 UI 之间缺少持久待提交队列

saveQueue、失败草稿、编辑器都在内容脚本内存中。重试能幂等，但刷新/导航会销毁尚未确认的内容。pending 是布尔值，不是统一操作状态机；重试和 clear 尚未全部进入同一串行队列。
建议：后台持久 outbox 记录 opId 与请求快照；前端只显示 confirmed / pending / failed 状态；统一普通保存、删除、清空与重试调度。恢复不能把旧页草稿写入新页。
验收：发送前、事务中、提交后回包前分别杀 Worker/刷新；要么确认保存，要么可恢复草稿；不能出现重复记录。

### P1：时间戳不适合作为长期并发版本

expectedUpdatedAt 作为 CAS 条件。同毫秒写入可能复用时间值，撤销会写回旧快照的时间，存在旧版本再次成为有效版本的 ABA 风险。
建议：后台生成不可复用的 revision，提交只比较 revision；撤销作为新提交而不是回退版本。需要连同消息、备份兼容和导入策略一起设计，不能只改一处时间戳。
验收：A/B 标签编辑、撤销、再编辑，旧请求始终拒绝；重复 opId 成功返回同一结果。

### P1：图形重排与旧身份的歧义

普通内容块高度/换行改变时，坐标仍保留像素偏移并标为 uncertain，无法证明圈住的仍是同一段。旧图形缺少帖子身份，同文字和空容器也可能相似。
建议：区分唯一确认、待确认和失联；失去可靠内容身份时禁止自动绑定/编辑；结合块文本、图片来源、所属帖子、几何变化做保守判定。旋转/3D/object-fit 需要明确支持边界及实测。
验收：不同帖子的相同文字、重复图片、隐藏后再显示、大幅重排，不能无提示贴到另一内容。

### P2：大页面与长期使用性能

openRoots 每 2 秒扫描全树；失联图形解析可在几何刷新期间 queryAll 全文查找；文字索引按 UTF-16 单元存对象；超长自由笔迹每帧重建数组并运行描边算法。关闭界面未停止全部订阅。operations 幂等表没有清理策略。
建议：内容/布局修订号分开，锚点身份查找只在内容变更时执行、几何更新只读已验证元素；发现 Shadow Root 降频并限定新增子树；采样合帧/简化；定义幂等记录保留窗口再安全回收。
验收：真实长文章、滚动信息流、500+标记、长笔迹、反复挂载卸载，提供帧耗时/内存数据；本轮没有量化性能结论。

### P1：公开环境覆盖不足

独立 Chromium 的结构夹具能验证已知结构，但不能替代真实站点、操作系统、Chrome 版本、触控/触控笔实测。关闭后的刷新、SPA保存竞态、嵌套弹窗等需要独立矩阵。
当前不支持跨域 iframe、封闭 Shadow DOM、PDF、未加载虚拟列表项。不得宣传 99% 兼容或“所有网页可用”。chenip.cn / 登录 X 仍未新增现场验收。

## 验证

29 项 Vitest 单元测试通过；21 组独立持久 Chromium 扩展测试通过，含本轮新增手势用例。类型检查、生产构建及权限清单检查通过。
现有覆盖还包括：刷新/重开、嵌套滚动、Shadow DOM、根节点 zoom/transform、模态窗口、Worker 重启、多标签冲突、导入事务回滚、本地 HTML、写入失败重试。
通知挂起、并发注入与长期性能未做完整故障/负载验证。
